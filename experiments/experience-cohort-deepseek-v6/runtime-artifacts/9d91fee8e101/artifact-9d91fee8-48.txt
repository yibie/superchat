## 2. Fixity: Bit-Level Integrity (Verified)

### OAIS (650.0-M-3, §1.6.2)

Fixity Information is "the information which documents the mechanisms that ensure that the Content Data Object has not been altered in an undocumented manner." It is one component of Preservation Description Information (PDI), alongside Provenance, Context, Reference, and Access Rights Information. Examples include CRC codes, checksums, and message digests.

### PREMIS v3.0

The `fixity` container (1.5.2) applies to File and Bitstream Objects with mandatory `messageDigestAlgorithm` (1.5.2.1) and `messageDigest` (1.5.2.2), plus optional `messageDigestOriginator` (1.5.2.3). The `signatureInformation` container (1.8) provides seven sub-components for digital signatures. PREMIS distinguishes the stored baseline fixity value from fixity-checking *events*, which are recorded via the Event entity with outcome, date/time, and linked Agents.

**Verified against:** PREMIS v3.0 hierarchical listing, confirming exact semantic unit numbering and applicability (File, Bitstream).

### ISO 16363 (652.0-M-2)

Metric 4.4.2 requires fixity checking during AIP preservation. Section 3.3 addresses "Procedural Accountability and Preservation Policy Framework." The 2025 edition expands §3.3.1 "for better consistency with ISO 14721."

### Critical Limits (Verified)

- **NDSA 2017 Fixity Survey** (164 responses, 89 completed): 84.1% utilize fixity, but practices vary widely. 73% collect externally-provided fixity "if available" but many "do not receive fixity values from record creators." MD5 remains most used (42.96%), SHA-256 at 25.19%, SHA-1 at 20.74%. Key challenges: lack of resources, software limitations, inability to automate on non-networked storage.

- **Aturban et al. (2023, PLOS ONE):** 16,627 mementos from 17 public web archives, downloaded 39 times over 442 days. 88.45% produced more than one unique hash; ~16% always produced different hashes. Causes: URL rewriting, JavaScript injection, evolving replay software, changing embedded resources. **Verified:** The paper explicitly concludes "conventional hashing functions are not suitable for replayed archived web pages" and calls for "archive-aware hashing."

**Corrective note:** The analyst described this as a "documented contradiction" to hash-based fixity assumptions. The characterization is valid but should be scoped: the finding applies specifically to *replayed* web archive mementos accessed via Wayback-style replay software, not to WARC files at rest. The standards framework remains applicable to stored AIPs.

## 3. Provenance: Chain of Custody (Verified)

### OAIS (650.0-M-3, §2.3)

Provenance Information "describes the source of the Content Data Object, who has had custody of it since its origination, and its history (including processing history)." OAIS explicitly links provenance to authenticity: "Provenance Information adds to the evidence to support Authenticity."

### PREMIS v3.0

Provenance is implemented through the **Event entity** (2.1–2.7): `eventIdentifier`, `eventType` (controlled vocabulary at id.loc.gov/vocabulary/preservation/eventType), `eventDateTime`, `eventDetailInformation`, `eventOutcomeInformation`, and linking Agent/Object identifiers. The `relationship` container (1.13) includes `relatedEventIdentifier` (1.13.4) to link derivation relationships to the causal Event, with `relatedEventSequence` for ordered multi-step transformations.

**Verified against:** PREMIS hierarchical listing, Understanding PREMIS (2017), and the eventType controlled vocabulary URI.

### ISO 16363 (652.0-M-2, §4.1)

Ingest metrics require the repository to document provenance from the Producer and maintain records of all provenance from Ingest onward.

### Provenance Gaps (Verified)

- PREMIS leaves event granularity to repositories ("up to the repository which actions to record as events"). This is confirmed by the Understanding PREMIS document.
- No formal ratified W3C PROV-to-PREMIS mapping standard exists, though the PREMIS OWL ontology (v3.0 at id.loc.gov/ontologies/premis-3-0-0.html) provides linked-data representations.

## 4. Later Interpretability: The Most Architecturally Complex Dimension (Verified)

### OAIS (650.0-M-3, §2.3–2.4)

Three interdependent concepts:

1. **Representation Information:** "The information that maps a Data Object into more meaningful concepts." It is recursive — forming a **Representation Information Network (RIN)**. Figure 4-13 provides a worked example for a FITS file.

2. **Designated Community:** The identified group whose **Knowledge Base** determines how much Representation Information is needed.

3. **Preservation Objectives (NEW in 2025, §1.6.2):** "A specific achievable aim which can be carried out using the Information Object." These make "Independently Understandable" testable.

**Verified against:** CCSDS 650.0-M-3 Document Control notes confirming "The concept of Preservation Objectives has been introduced to allow 'Independently Understandable' to be more consistently testable."

### PREMIS v3.0

- `format` (1.5.4): format designation or registry link (e.g., PRONOM PUID)
- `environment` (1.9–1.12): Environment Objects as Intellectual Entities capturing hardware/software dependencies
- `significantProperties` (1.4): "characteristics of a particular object subjectively determined to be important to maintain through preservation actions"
- `creatingApplication` (1.5.5)
- `relationship` (1.13)

**Verified against:** PREMIS hierarchical listing confirming exact numbering and structure.

### PRONOM and InSPECT (Verified)

The UK National Archives' PRONOM registry provides persistent unique identifiers (PUIDs, e.g., `info:pronom/fmt/XX`) serving as concrete Representation Information. The InSPECT project (2007–2009) developed a Function-Behaviour-Structure methodology for identifying significant properties, defining them as: "The characteristics of an Information Object that must be maintained over time to ensure its continued access, use, and meaning, and its capacity to be accepted as evidence of what it purports to record."

**Corrective note:** The analyst states that PREMIS §1.4 says significant properties are "subjectively determined." The hierarchical listing does not include this language explicitly — it is from the full Data Dictionary narrative. The InSPECT framework independently confirms the relativistic nature of significance.

## 5. Integration Summary (Verified)

| Concern | OAIS (ISO 14721:2025) | PREMIS v3.0 | ISO 16363:2025 |
|---|---|---|---|
| **Fixity** | Fixity Information as PDI component (§1.6.2) | `fixity` container (1.5.2); `signatureInformation` (1.8); Event-based checks | Metrics for documented fixity, media refresh, integrity verification |
| **Provenance** | Provenance Information: source, custody, history; supports Authenticity (§2.3) | Event entity with controlled types, outcomes, linked Agents/Objects; derivation relationships (1.13) | Metrics for documented provenance chains, ingest procedures |
| **Interpretability** | Representation Information Network; Designated Community Knowledge Base; Preservation Objectives (2025) | `format` (1.5.4), `environment` (1.9–1.12), `significantProperties` (1.4); registries (PRONOM) | Preservation Planning metrics; new 4.3.5 for Preservation Objectives |

## 6. The 2025 OAIS Revision (Verified)

**Verified against CCSDS 650.0-M-3 Document Control notes (pp. v–vi):**

1. Preservation Objectives introduced (§1.6.2, §2.4) — allows testable Independent Understandability
2. Preservation Watch added to Preservation Planning Functional Entity
3. Information Package definition updated; PDI relationship to Content Data Object clarified
4. Additional preservation techniques (emulation, wrapping) described explicitly alongside Migration (§5.3)
5. Additional Archive interaction types (primary-supporting Archives, federated Archives, shared storage) added (§6)
6. Annex A reclassified as Informative; Annex B replaced with pointers to CCSDS website

**ISO 16363 2025 changes verified against CCSDS 652.0-M-2 Document Control (p. v) and NARA blog (Mar 2025):** 109→115 metrics; six new metrics (4.1.1.3, 4.1.1.4, 4.2.3.2, 4.2.3.3, 4.3.5, 5.1.1.7); "written"→"documented"; "metadata"→"information"; Preservation Objectives added to 4.1.1.3, 4.1.1.4, and new 4.3.5.

## 7. Reviewer's Conclusion

The analyst's work is **confirmed accurate** against primary sources on all material points. The three-standard architecture (OAIS/PREMIS/ISO 16363) provides a coherent, layered governance framework: OAIS defines the conceptual vocabulary and mandatory responsibilities; PREMIS supplies implementable metadata elements; ISO 16363 provides auditable evidence that both are functioning. The 2025 revisions close the gap between abstract requirements and testable outcomes through Preservation Objectives and Preservation Watch.

Two documented limitations deserve emphasis: (1) hash-based fixity fails for replayed web archive mementos (Aturban et al., 2023), though stored WARC files remain verifiable; and (2) the standards deliberately avoid prescribing implementation details (algorithm choice, check frequency, event granularity), leaving operational maturity dependent on institutional resources and community-developed tools.
