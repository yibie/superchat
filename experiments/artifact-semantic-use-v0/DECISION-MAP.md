## later-authorization: Decide Whether A Preflight Is Worth Designing

Blocked by: v03-remediation
Status: resolved
Type: Task

### Question

If and only if a later offline revision passes fresh review, is one
sacrificial transport preflight worth a new contract?

### Answer

Yes, but only as a later transport-integration check; this ticket does not
authorize running it.  One pinned, read-only, non-secret provider request can
check that the current provider/model/config path yields the Decision Snapshot
and tool trajectory required by the offline scorer.  It cannot measure
Semantic Use, Task Effect or Learning, and one success cannot establish a
provider-general wire contract.

The existing order `V2 → P3` is invalid.  V2 rejects a Candidate that is
manually inserted without historical lineage and a Promotion ID, while P3 is
the phase that creates human-gated Promotion and selects that Candidate into a
future View.  The corrected frontier is therefore product-first:

```text
P3a human disposition + scoped Experience View
  → V2a scorer-compatibility decision
  → V2a 16-assignment evaluator contract
  → V2a local/fake-provider product harness closure
  → transport-preflight explicit execution decision
  → V2 held-out provider cohort
```

No provider work starts merely because this design decision is resolved.

Canonical ERT is 705 total / 688 passed / 17 skipped / 0 unexpected.  No model
or provider was called.  This proves product selection and evidence wiring,
not that a model used the Candidate or that task behavior improved.  The
`user` Actor field is a host contract, not cryptographic human authentication;
no model-callable writer exists.
