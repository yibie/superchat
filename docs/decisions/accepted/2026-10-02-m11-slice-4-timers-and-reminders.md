# Decision: M11 第 4 片——定时与提醒

Status: accepted — 用户，2026-10-02："开始第四片"。条目来自 [workspace 契约](2026-10-01-workspace-work-record-session-rules.md)的 T1–T3；"leader 的选择"一节是 leader 在这句话之下定的机制，随本片向用户报告。

## Problem

"20 分钟后提醒我给妈妈打电话"在目标批次里只有 1/3 做成（P3）：superchat 没有定时器，模型只能用 `eval_elisp` 调 `run-at-time`，这样的定时器重启就没了，到点也只是在 Emacs 里执行一段代码，对话里没有任何记录。

## Decision

新模块 `superchat-timer.el`。定时器是独立的对象，属于设它的那段对话的 workspace（T1）：

- **存在哪：** 记录上的三种事实——`timer.created`（设）、`timer.fired`（到点）、`timer.cancelled`（取消），都记在对话的记录上，不另建表。哪些还没到点，每次从这些事实里算出来，所以重启后自然还在。
- **到点做什么：** 纯提醒（T2）在 Emacs 里提示（回显区加响铃），在该 workspace 的主对话里留一行"Reminder: …"，不启动模型；带任务的（T3）另外在主对话里把任务文字作为一条请求发出去。这一行显示在对话窗口里，不作为对话历史发给模型。
- **错过了：** superchat 加载完之后，过了点的补发一次，并标明原定时间；重复型只补最近一次。
- **怎么设：** 给模型三个工具：`timer_create`（文字、提醒还是任务、几分钟后或某个时刻、可选每小时/每天/每周）、`timer_list`、`timer_cancel`。它们是内置工具，放在默认工具清单里，任何权限级别下都不用审批。
- **开关：** 插件行 `timers`，挂上时给所有未到点的定时器上好 Emacs 定时器（先补发错过的），卸下时全部撤掉；无界面配置下关闭。

验收：`scripts/timer-regression.el`；目标批次 P3 改为检查 superchat 的定时器；一个跨重启的真实任务：设一个几分钟后的提醒，退出 Emacs，过点后再启动，提醒补发并留在主对话里。

## leader 的选择

1. **事实记在记录上，不另建表。** 记录本来就是只追加、可回放的，workspace 的认定、对话的配置都是这样存的；这样也不必处理"表和记录不一致"。
2. **到点的一行记在 workspace 的主对话上，**即到点那一刻最近活动的那段；临时对话里设的定时器就在那段临时对话里。
3. **提示用回显区加响铃。** 不依赖系统通知；用户可以换 `superchat-timer-notify-function`。
4. **工具放进默认清单并算内置工具。** 作为插件工具注册的话，默认权限级别下每设一个提醒都要用户批准一次。代价是每次请求多三个工具的说明；默认清单从 9 个变成 12 个，三套钉死这份清单的回归随之改（`composition`、`m7-buffer-first`，以及 `superchat-select-tools.el` 里的后备副本）。
5. **时间只收两种写法：** 几分钟后，或本地时间"YYYY-MM-DD HH:MM"。"明天早上"这类说法由模型换算，工具的回答里写明定在了几点，模型照此告诉用户。
6. **补发推迟到加载完成之后**（`run-at-time 0`），免得一个错过的任务在 `require` 的半中间启动模型。

## Alternatives considered

**用 Emacs 自己的 `run-at-time` 加一个保存文件。** 输在要另外维护一份状态，而且对话里没有记录。

**到点一律启动模型（Holon 的做法）。** 输在契约 T2：纯提醒不启动模型。

**另开一段对话给每次定时任务（Codex 可选的做法）。** 输在契约 T2/T3 写的是留在主对话里。

## Consequences

- 默认工具清单多三个工具，每次请求多带它们的说明。
- 定时器事实留在记录上，历史里看得到"Reminder set for …"和"Reminder: …"两行。
- 同一份数据目录被两个 Emacs 同时打开时，同一个提醒会响两次；本片不处理。
