# Decision: 你在原文上写批注，攒几处，一次交给模型

Status: accepted — 用户 2026-11-06。用户给了 https://github.com/SreenivasVRao/reviewer.el ，说"我发现这个插件的体验非常符合需要"。我读了它的源码（551 行），建议 superchat 接上它，用户答："让 superchat 自己实现吧，不依赖它"。按键、格式、发出后怎么处理是实现时定的，都可以改。

## Problem

superchat 已有三种"就着原文说话"的方式，都不是"你攒好几处意见，一起交出去"：

- `superchat-annotate`：模型写意见，挂在原文上，方向相反（[挂在原文上的批注](2026-10-10-remarks-hung-on-the-text.md)）。
- `superchat-inline`：你问一处，马上答在原地。
- `superchat-rewrite-region`：一段配一条指令，马上改。

要对三个文件里的五处说话，只能自己把每处的位置和原文打进消息里。

reviewer.el 的做法：选一段，写一句，文字不变；攒好后整理成一份 org（文件、行号、原文、意见），复制或存进 `/tmp`，你再贴给 Agent。它的短处是交接要自己贴（贴进输入区，正是用户 11-06 嫌占地方的做法）、一次只整理一个 buffer、不保存。

## Decision

**`superchat-note.el`，不依赖 reviewer.el。**

- **写：** `M-x superchat-note`。有选区用选区，没有用光标处的符号，再没有用这一行。下面弹出一个小 buffer 写字，`C-c C-c` 留下，`C-c C-k` 不动。在已有的批注上再按一次是改它的字；字清空就是删掉。原文不变，buffer 也不算改过。
- **看：** 写过批注的文字有底色；光标走到上面，回显区显示那句批注。
- **删：** `superchat-note-delete` 删光标处的一条，有选区时删选区里的全部；`superchat-note-clear` 问过你再删这个 buffer 的全部。
- **列表：** `M-x superchat-notes` 列出所有 buffer 和文件里的批注。`RET` 跳到原文，`e` 改字，`d` 删，`a` 附上，`g` 重读。
- **交出去：** `M-x superchat-note-attach` 把**所有** buffer 里的批注作为一份附件，放在对话 `* User:` 上面，和 `[bring in]` 用的是同一个位置（[交给模型的只经过你发的消息](2026-10-31-bringing-a-conclusion-into-your-message.md)）。输入区还是你的。`C-c C-b` 展开看到的就是要发的原文，`C-u C-c C-b` 去掉。附件跟着批注变：附上以后再写、改、删批注，发出去的是发送那一刻的样子；全删光了附件就不显示，也不发。对话是眼前的那个，没有就用 `M-x superchat` 从当前位置打开的那个。
- **发出去的样子：**

  ```
  My notes on the text (2):

  1. bar.el, line 6:
  > (* 2 x)
  My note: 改成 (+ x x)

  2. foo.el, line 4:
  > (or name "world")
  My note: 这里换成 if-let
  ```

  文件名相对于对话的项目根目录。原文的每一行以 `> ` 开头，里面的 `/命令`、`@模型` 不会触发（`superchat-core--quoted-at-p`）。你写的批注不加引号，是你的话。
- **发出后，这些批注就了结了，** 从 buffer 和保存的文件里去掉。发送之后才写的批注不受影响。
- **保存：** 文件上的批注存在 `superchat-note-file`（默认是数据目录里的 `notes.eld`）。关掉 buffer、重启 Emacs 以后，再打开那个文件，批注按它所在的那段文字找回来；找不到就挂在原来那一行，标着"its text is gone"，字还在，交出去时写明 "that text is not there any more"。没有文件的 buffer（比如 diff）上的批注只活到 buffer 关掉。
- **键：** 一个前缀键表 `superchat-note-map`，由你绑定，例如 `(keymap-global-set "C-c n" superchat-note-map)`。里面 `n` 写、`d` 删、`D` 全删、`l` 列表、`a` 附上、`]`/`[` 下一条/上一条。superchat 不替你占全局键。

## 实现时定的

- **附件可以是"活的"：** `superchat-butler--attach` 的 WHAT 和 WORDS 可以是函数，每次显示和发送时现问；发出后调用 `:sent` 函数。批注用的就是这个，以后别的东西也可以用。字为空的附件不显示也不发。
- **编号和 "My note:"：** 第一版没有编号，真实运行里模型把两条批注的归属看混了，说第二条"页面上标的 bar.el, line 6 是错的定位"。加上编号和 "My note:" 以后 3/3 分得清。
- **一段原文最多带 30 行**（`superchat-note-quoted-lines`），多的写 "and N lines more"。
- **buffer 没保存时** 写明 "not saved; lines as in my buffer"：模型读磁盘，行号会对不上。
- **找回时** 在原来那一行前后找同样的文字，取离得近的那一处。
- **批注不存进 Tape：** 它们是会改、会删的东西，不是发生过的事。发出去的那条消息照常进 Tape。

## 这一步没有做的

- 审阅屏（`superchat-changes-review`）里直接在差异上写批注。批注能写在任何 buffer 上，审阅屏也可以，但"让模型按批注重改"没有专门接。
- reviewer.el 的 transient 菜单和 posframe 弹窗：前缀键表加回显区代替。
- 批注的回复线程。

## Alternatives considered

**接 reviewer.el，不自己写。** 用户定了不依赖它。

**批注当作 Tape 事实。** 没选：批注会改会删，记成事实要处理"改了第几版"；发出去的消息已经在 Tape 里。

**发出后保留批注，标成"已发"。** 没选：下次附上时要分辨哪些发过；模型改代码时文字会动，留着的标记也会错位。要再看，在对话里看那条消息。

**整理成 org 源码块（reviewer.el 的格式）。** 没选：源码块里的 `/命令` 会被当成命令；`> ` 引用行是对话里"别人的字"已有的写法。

## Consequences

- **安全：** 附件发出去时，原文和你的批注都发给模型服务商，和你自己把它们打进消息一样。附件在发之前看得到全文。
- **`kill-buffer-hook` 和 `find-file-hook` 上各多一个函数，** 对没有批注的 buffer 只做一次查找。
- **`notes.eld` 每改一次批注写一次，** 文件很小。

## 验证

- `scripts/note-regression.el`，25 个测试：原文和"改过"标记不变；同一个键改字、清空删掉；取消不动；没有选区时用符号；回显区显示且只显示一次；删一条和删选区；关掉再打开按文字找回（上面多了两行也找得到），两处一样的文字取近的；文字没了字还在并写明；没有文件的 buffer 不写文件；附上的是所有 buffer 的批注、在 `* User:` 上面、输入区空着；附件跟着批注变，删光就不发；发出去模型收到、批注了结；发送后写的不算发过；去掉附件批注还在；附两次只有一份；引用行里的命令不触发；没保存写明；长原文截断；没有批注时附上会提示；列表有全部、`d` 删、`RET` 打开文件并跳到原文。
- 故意改坏 30 处，第一轮 7 处没抓到：2 处是多余的代码（已删），1 处是我写的改坏本身不改变行为，另外 4 处补了测试后全部抓到。
- 真窗口、真按键、真 DeepSeek，5 次：
  - 第 1 次实验脚本自己出错。
  - 第 2 次没加编号，模型最后答对了，但把归属说混了。
  - 加编号后 3/3 全部检查通过：在两个文件里写批注、回显区显示、列表、附上后输入区空着、展开、发送、回答写对两个文件和行号、批注了结、文件没改。每次 2–9 秒，约 4600–9900 提示 token。
- 整套回归 134 个文件 2232 项，只有 `m5-regression` 那 3 项不过，这之前就不过。
- 没在你的 Emacs 里用过；没有前缀键，要你自己绑。
