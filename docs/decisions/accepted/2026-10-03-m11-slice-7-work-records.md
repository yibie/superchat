# Decision: M11 第 7 片——工作记录

Status: accepted — 用户，2026-10-03："让 worker agent 解决 a2，然后回到第 7 片"。条目来自 [workspace 契约](2026-10-01-workspace-work-record-session-rules.md)的 K1–K9、K11、K12；机制取自 Holon（[参考实现里的事实](../../research/workspace-and-work-record-references.md)）。"leader 的选择"一节是 leader 在这句话之下定的机制，随本片向用户报告。

## Problem

一件要跨几次对话才做得完的事，现在没有地方记"做到哪了、下一步为什么还不能做、回来后从哪接上"。换一段对话、重启 Emacs 之后，模型只能靠回忆搜索去碰运气。

## Decision

| 小片 | 内容 | 契约条目 |
|---|---|---|
| 7.1 | 记录的存放：记录上的事实（建立、更新、等待、完成、当前记录、产品附上的事实），从事实里算出每条记录的现状；每次执行结束由产品得出结局 | K1、K3、K7、K11、K12 |
| 7.2 | 给模型一个工具 `work_record`：建、更新（四个问题）、登记等待、完成（必须附结论）、读 | K2–K6、K11 |
| 7.3 | 请求里带上：当前记录的全文；本 workspace 其它记录的清单，按"可继续、在等用户、在等别的、最近完成"分组；并写明最近几轮只是背景 | K8、K9 |
| 7.4 | 给用户：列出记录的命令，用户自己标完成 | K11 |
| 7.5 | 何时建、何时更新的指引；真实任务验收 | K4、K5 |

验收：各小片的回归；一个要两段对话才做完的真实任务——第一段做到一半停下，第二段（新对话，可以在重启之后）接着做完；记录能回答四个问题，结局由产品得出。

## leader 的选择

1. **记录是记录上的事实，不另建表。** 和定时器一样：`work.created`、`work.updated`、`work.waiting`、`work.completed`、`work.focused`、`work.facts`、`work.outcome`，都只追加；某条记录现在是什么样，从事实里算出来（K12 的"只追加"）。需要长计划时，计划是数据目录下 `work/<编号>/plan.md`，不放进用户的项目。
2. **一个工具，不是五个。** `work_record` 带一个 `action` 参数（`start`、`update`、`wait`、`done`、`read`）。第 6 片量过：工具说明占请求字节的一半多，用户在意工具个数。
3. **更新就是回答四个问题。** `start` 记"要交付什么"；`update` 的字段是"做到哪里了""下一步为什么还不能做""回来后从哪里接上"；只写变化的部分，其余沿用上一次。
4. **当前记录按对话算。** `start` 让新记录成为这段对话的当前记录；`done` 之后当前记录清空。同一时刻一段对话只有一条当前记录（K6）。
5. **工作记录只属于有根目录的 workspace。** 临时对话里调用 `start` 会被告知"这里不保存，用 `/workspace <目录>` 设一个 workspace"——与第 2 片对"记住"的处理一致（W10）。
6. **结局由产品得出（K7）。** 一次执行结束时，看这次执行里登记了什么：调用了 `done` 是"完成"；登记了等待且没撤销是"等待"；执行失败是"失败"；其余是"可继续"。不读答复的文字。"可继续"的记录由产品接着安排下一次执行，这部分随唤醒机制放到下一片（K10）；本片只得出并显示结局。
7. **产品附上的事实（K3）。** 每次执行结束，把这次执行改过的 buffer 和文件（与 `/changes` 用的同一来源）附在当前记录上；模型写不了这一部分。
8. **请求里的位置。** 当前记录和清单放在"上下文"这一段（和 Emacs 来源、窗口摆法同处），不放进系统文字，因为它每次执行都会变。

## Alternatives considered

**五个独立的工具（Holon 的做法）。** 输在每次请求多四个工具的说明。

**记录写成 workspace 目录里的文件。** 契约讨论时已否决：每次更新都会改动用户的工作副本，临时 workspace 也没有目录。

**本片就让产品自动接着做"可继续"的记录。** 输在自动启动模型要有唤醒和新对话的机制（K10），那是下一片的内容；先把结局算对、显示出来。

## Consequences

- 默认工具清单多一个 `work_record`。
- 有当前记录或本 workspace 有记录时，请求多一段文字。
