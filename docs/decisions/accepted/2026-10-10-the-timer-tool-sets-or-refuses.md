# Decision: `timer_create` 设下的定时器会响，否则就明说拒绝

Status: accepted — 用户，2026-10-10。F4 修完后我报告"定时器那一行卸下后 `timer_create` 会不会有同样的问题，我没有查"，并建议先查它："它和 F4 是同一类问题，查一下就知道有没有缺口，有的话修法可以照搬"。用户答："同意，继续"。"实现中定下的几点"是实现时定的，随本次向用户报告，用户可以改。

## Problem

查的结果是有缺口。把 `timers` 这一行卸下之后，三个定时器工具还在（它们登记在默认工具面里，不随这一行卸下）。探针里，模型调用 `timer_create`：

- 提醒得到的回答是"the user will be reminded at …"，任务得到的是"the task will run at …"。
- 记录里写下了这两个定时器。
- 上弦的数量是 0。

到点什么都不会发生；要等这一行重新挂上，错过的才会补触发一次。工具回答成功，实际没有兑现，和 F4 是同一种毛病。

## Decision

- **这一行卸下时，`timer_create` 被拒绝。** 回答说明这个 Emacs 里定时器关着、没有设下定时器、到点什么都不会发生，让模型告诉用户。什么都不写。提醒、任务、重复的、给钟点的，都一样。
- **`timer_list` 照常列出，并多说一句**：定时器关着，下面列的在重新打开之前都不会响。
- **`timer_cancel` 不变。** 之前设下的仍然可以取消。
- **这一行重新挂上后**，`timer_create` 又能设下并上弦。

## 实现中定下的几点

- 检查放在工具入口（`superchat-timer-tool-create`），没有放进 `superchat-timer-create`。产品代码里只有工具这一处调用它，但测试里有二十多处直接调用，其中有的正是在这一行卸下时建、再挂上看补触发。
- 给模型看的 `timer_create` 说明没有改。
- 这一行卸下之前已经设下的定时器不动；重新挂上时照原有逻辑补触发和上弦。

## Alternatives considered

**这一行卸下时把三个工具一起撤掉。** 没选：和 F4 一样，这要在工具面和功能行之间建立依赖，是更大的改动；而且列出和取消在卸下时仍然有用。

**照样写下，只在回答里提醒"要等重新打开才会响"。** 没选：模型很可能照旧告诉用户"到时提醒你"，用户等不到。

## Acceptance criteria

`scripts/timer-tool-regression.el`，5 个测试：

- 这一行卸下，经真实的工具调用设提醒：模型在工具的回答里被告知定时器关着，记录里没有新建的定时器，没有上弦。
- 这一行卸下：提醒、任务、重复的任务都被拒绝，回答里有"no timer was set"，什么都没写。
- 这一行卸下：列表说明定时器关着，并仍然列出之前设下的；取消可用。
- 这一行挂着：回答和以前一样，不提"关着"；写下一个定时器并上弦（护栏）。
- 重新挂上：能设下并上弦。

在旧代码上 4 个失败，1 个通过（护栏）。对新代码做了 6 处变异，全部被发现。

## 没有解决的

- 能力的工具、收集器、观察者、计时资源之间仍然没有明确的依赖；这次和 F4 一样，只保证不兑现的承诺会被拒绝。
- 没有用真实模型验证，没有真人在键盘前验证。
