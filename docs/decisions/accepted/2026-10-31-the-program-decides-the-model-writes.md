# Decision: 定时命令的简报：说不说由程序决定，模型只写那几句话

Status: accepted — 用户，2026-10-31 说主动 Agent 要能"定期检查 github 的 star 进行简报"；同日对"写死命令、批准一次"答"是"，对"没有结论时"那张表答"是"。2026-11-01 我说下一步是第 5 步的其余部分，用户答 "follow you heart"，所以这一步由我选。[提案](../proposed/2026-10-31-an-agent-that-acts-without-being-asked.md)第 5 步的第 1 档就是这里。"实现时定的"各条都可以改。

## Problem

[第 0 档](2026-10-31-a-command-that-runs-by-itself.md)能查出 star 数变了，说的是程序拼的一行：`123 (was 120)`。用户要的简报是几句人话，比如"昨天多了 3 个 star，其中 2 个来自同一个组织"，而命令的输出可能是一张列表或一段 JSON，程序拼不出来。

让模型来写又有两个风险：每次都花钱；模型读的是环境里的内容，里面可能夹带"别告诉用户"这样的文字。如果由模型决定说不说，别人写的一行字就能让一次变化消失。

## Decision

**说不说由程序决定，模型只写那几句话。** 比较和"连续失败 3 次才说"都和第 0 档一样，模型的回答不影响有没有这一行，也不影响它算"变了"还是"没变"。模型手里没有工具，夹带的指令没有手可用。

**`timer_create` 多一个 `brief`，只跟命令一起用。** 审批卡片上写明这一点：批准的不再只是一条命令，还有"每次要说话时，把输出交给模型"。

**这一行要说的时候，才调用模型：**

| 情况 | 模型调用 | 这一行 |
|---|---|---|
| 输出没变 | 0 次 | 不出声 |
| 输出变了 | 1 次 | 模型写的第一行，标明是模型的话 |
| `report_unchanged`，输出没变 | 1 次 | 模型写的第一行，标明是模型的话 |
| 设完立刻跑的那一次 | 1 次 | 模型写的第一行，模式行不加 |
| 失败 | 0 次 | 程序的话 |
| 模型失败、超时、被停掉 | 已花掉的那 1 次 | 程序的话，标明模型没有写 |

**按 `RET` 看模型的全文和原始输出；按 `t` 带进你的消息时两样都带。** 这一行只是模型的话，原始输出总是在。

**模型的全文和 token 数记在这次结果上。** 规则那一行显示最近一次是什么时候、结果如何、一共跑了几次、变了几次、写了几次、用了多少 token，所以"没消息"能分清是查过没事还是根本没查。

## 实现时定的

- **跑在管家的固定 Session 上，actor 是 `brief`，surface 是 `timer-brief`，由 `timers` 这一行注册。** 这个 Session 不在已知对话的列表里；临时 Session 会出现在那里。actor 不算"无人值守"，否则这次执行自己又成了一条通知。同一时间只写一份，另一份排队。
- **模型看到的只有写死的说明、这条检查的名字、命令、上次和这次的输出，**没有对话、记忆和规矩。请求里只有一条 system 和一条 user，有测试锁定。
- **一次最多 120 秒**（`superchat-timer-note-seconds`），**最多 400 个输出 token。** 上限是这两个加上重复周期：每天的规则一天最多一次模型调用，每小时的最多 24 次。提案里"每条规则的次数上限"这个数字没有定，这一步也不定。
- **模型写完才记结果。** 比较用的基准是上一条结果。如果先记再等模型，Emacs 在等待时退出，下一次比较会认为没变，这次变化就丢了。现在退出后下一次仍算"变了"，再说一次。所以不需要补写的代码。代价是：这一次的 `command.result` 比命令结束晚几秒。
- **写的时候又到点，这一次跳过并留记录，**和命令还没跑完时一样。
- **取消定时器或关掉 `timers` 这一行时，正在写的一起停掉，什么都不记。** 在列表里按 `k` 只停这次执行，程序照常说那一行。
- **设完立刻跑的那一次也写。** 用户当场看到简报长什么样，不满意可以马上改。多花一次模型调用。
- **这一行的文字标明来源：** `changed (the model's words): …`，模型没写时是 `changed, no note from the model: …`。
- **全文最多 2000 字符，** Tape 上要放得下。**这一行最多 400 宽：**答案的第一行限 200，但简报整段都是要说的话；真实运行里一半超过 200，没有超过 400 的。
- **语言跟用户走。** 提示里写"用户给这条检查起的名字说明了他们用什么语言"。写"用描述的语言"时，中文名字配英文输出，5 次全写英文；写"用检查名字的语言"时，英文名字 `open issues` 有 3/5 写成德文；举"中文"这个例子时，英文名字有 6/15 写成中文。现在的写法：中文名字 40/41，英文名字 60/62（[数字](../../research/super-agent.md#简报)）。
- **工具告诉模型"正在跑"。** 带 `brief` 时第一次的结果要等简报写完才记下，所以命令已经跑完、简报还在写时，工具也说 "It is running once now"。第一次跑失败时不交给模型，改了再设的路不受影响。
- **失败不交给模型。** 退出码和标准错误已经说清楚了，失败时花钱也没有意义。
- **规则那一行的统计放在最前面，** 因为列表这一列会切掉长内容：`ran 4 times, last: no change (…), 1 change, 2 notes, 350 tokens; next …: 命令`。下次时间因此可能被切掉。`RET` 在这一行上显示最新的输出和这些统计，还没跑过时去设它的对话。只有带命令的定时器有统计。
- **一次性的命令到点后已经不算待办，取消不了，它的简报照常说完。** 在列表里按 `k` 可以停这次执行。

## 这一步没有做的

**`dropped` 动作。** 上面那张表只对规则启动的执行生效，你亲自设的定时任务和被唤醒的工作记录都照旧留标记（[2026-10-10](2026-10-10-a-notice-for-work-nobody-watched.md)）。第 0、1 档没有模型工具，所以现在没有谁能用它，移到第 7 步和第 2 档一起做。

**重复的 `kind: task` 算不算规则。** 也留到第 7 步。

**每条规则的次数上限和任务的统计。** 见上。

## Alternatives considered

**让模型决定有没有东西可说。** 没选：夹带的文字可能让它什么都不说，而且程序已经能判断。这是这条记录的核心。

**没变时不调用模型，复用上一次的简报。** 没选：上一次写的是"比昨天多 3 个"，今天原样显示就是错的。

**没变时不调用模型，只显示程序的一行。** 没选：`report_unchanged` 是用户要求每次都说，设了 `brief` 就是要人话，而费用已经被重复周期限住。这条可以改。

**用 `submit-blocking`（magit 的做法）。** 没选：等模型时 Emacs 不响应。这个方案的前提是不打扰手上的工作。

**每条规则一段后台对话，历史就是往期简报（提案原来的写法）。** 没选：会多一堆 buffer，模型也不需要历史，往期简报在管家里。

**先记结果，再把简报补写成另一个事实。** 没选：要处理"结果写了、简报没写"这种状态，还要改比较的基准。

**临时 Session（`ephemeral-…`）。** 没选：`superchat-view-session-ids` 会把它们当作已知对话列出来。

## Consequences

- **安全：** 模型读的是不可信的输出。它手里没有工具，但写的话会显示在门铃、管家和列表里，按 `t` 后还会进你的消息。它可能照着夹带的文字写，比如写一条建议你运行某个命令。所以这一行标明"模型的话"，`RET` 总能看到原始输出，解析器仍然挡住引用里的触发词（[接手](2026-10-31-bringing-a-conclusion-into-your-message.md)）。
- **费用：** 设了 `brief` 的规则每次说话多一次模型调用，用户没开口也花钱。`report_unchanged` 加每小时重复时一天最多 24 次。
- 输出超过 6000 字节时，模型只看到前 6000 字节，并被告知总长度。
- 模型默认用全局模型，不跟随设它的那段对话的模型。
- 门铃那一行是 Org 正文。第 0 档这一行由程序拼，这里由模型写，所以模型写出 `[[a][b]]` 时显示成链接。`RET` 显示原文。
- 命令的输出会发给模型服务商。第 0 档的输出不出 Emacs，设了 `brief` 就出了，所以卡片上写明。
- 简报的请求和回答在管家 Session 的 Tape 上（`intent.received`、`response.completed`）。第二阶段管家有自己的问答时，组对话历史要跳过它们。
- Emacs 退出时正在写的简报丢失，下一次到点再说；如果那次之后输出又变回去，这次变化就没人说了。

## 验证

- `scripts/timer-brief-regression.el`，脚本模型，61 个测试。先写的 45 个在改代码前都失败，其中多数只是因为函数还不存在。后面 16 个跟着真实运行和故意改坏代码补上，靠下面的检查确认它们抓得到。
- 故意改坏代码：第一轮 92 处漏了 11 处。1 处说明那段代码多余（执行的编号已经由状态回调给出），已删；其余 10 处补了测试。最后一版 92 处全抓到。
- 全量：127 个文件 1811 个测试，不干净的只有 `m5-regression` 3 个失败和一个故意失败的演示，都与这次无关。M3 单独全跑：139 个，137 个通过，2 个跳过，M3 回归文件没有改动。
- 真实窗口、真实按键、DeepSeek `deepseek-v4-flash`，结果在[研究页](../../research/super-agent.md#简报)。程序说这一行 35/35，夹带指令的 10 次都没有照做，用平常的话选对 24/25，4 分多钟的工作 25/25 答对，来自检查的模型请求 3 次。

没有验证的：真人；图形窗口；到点是脚本触发的，没有等到真的第二天；Emacs 在写简报时退出再启动（只有脚本模型模拟）；在列表里按 `k` 停掉（只有脚本模型）；更狡猾的夹带写法；DeepSeek 以外的模型。
