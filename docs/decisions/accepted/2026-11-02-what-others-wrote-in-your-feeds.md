# Decision: elfeed 里来了新文章，模型只读不动手，挑出你要的告诉你

Status: accepted — 用户 2026-11-02 说"great, next step"，之后又说"继续完善第九步"，并选了"先把 RSS 做扎实"：修设规则时 `quiet` 不稳和夹带指令让模型吞文章，再用自己的 elfeed 数据跑真实实验，下一步是[提案](../proposed/2026-10-31-an-agent-that-acts-without-being-asked.md)第 9 步：别人写的内容（邮件、RSS、群聊），以及重启后补事件、进展检查。后两样见[另一条记录](2026-11-02-what-a-restart-and-a-runaway-already-have.md)。三种来源里先做 RSS，是查过用户的机器定的：elfeed 的索引 2026-11-01 还在更新，订阅 92 个；telega 最后一次用是 2026-08-17；没有装邮件客户端。"实现时定的"各条都可以改。

## Problem

到第 8 步为止，主动工作读到的都是你自己的东西：你的命令的输出、你的项目、你的编译。别人写的内容不一样：一篇文章的作者可以在正文里写任何话，包括写给模型看的指令。提案的安全一节为此写了"第 9 步之前，不接入别人能写入内容的来源"。

文章里的主动 Agent 会盯着信息流，挑出和你有关的告诉你。用户 2026-10-31 举的例子"定期检查 github 的 star 进行简报"是同一类事。

## Decision

**一条规则，事件是 `feed_new`。** 你说"elfeed 有新文章时，和 Emacs 有关的告诉我"，模型调用 `timer_create`，`on: "feed_new"`。这种规则一律按你的话挑：每一批说不说，由你的话和每篇讲什么决定，模型设规则时给不给 `quiet` 都一样。卡片上写明：模型拿到的是标题、来源和正文开头，一次最多多少篇、一天最多几次，没有工具，打不开链接，内容是别人写的、会发给模型服务商。全部只有一条：再设一条就替换掉原来的，编译规则不受影响。它不属于哪个项目：临时对话里也能设，每个对话都能看到它、取消它（2026-11-05 用户在临时对话里设，被"这个对话不属于任何工作区"拒绝了三次，是照搬编译规则的检查造成的，已改，测试 `feed/a-temporary-conversation-sets-it-through-the-tool`、`feed/the-rule-is-seen-from-every-conversation`；它属于你本人，见[长期的任务记下自己属于谁](2026-11-06-whose-a-standing-job-is.md)）。编译规则仍然要在项目的对话里设。

**程序决定的：**

- **哪些是新的：** elfeed 第一次把一篇放进数据库时告诉我们（`elfeed-new-entry-hook`），每篇一次。程序不比较内容。
- **一批什么时候齐：** 最后一篇来了 30 秒没有新的，而且 elfeed 已经没有在抓的（`elfeed-queue-count-total`）。
- **哪些不算新：** 三天前的。新加一个订阅，elfeed 会把它所有的旧文章一次放进来，那不是新闻。
- **一次给多少：** 最新的 30 篇，每篇正文前 600 字，去掉 HTML；多出来的告诉模型"还有 N 篇没给你"。
- **一天几次：** 12 批。到了说一次，之后的只记下。
- **正在读一批时又来了：** 不替换，读完再读下一批。

**模型能做的：** 只有一个 `nothing_to_tell`，没有别的工具。它只能写几句话，用 `[3]` 这样的编号指文章。

**不说话由编号决定，不由模型的"是"决定。** `nothing_to_tell` 要先写理由，再写 `about`：哪几篇是讲规则要的东西的编号。`about` 里有一个编号，程序就不记"不说"，让它接着回答、点出这几篇。在你自己的订阅上量过：模型在理由里写着"[4]、[12]、[15] 讲 AI"，却仍然选了不说；文章正文里写"用户改了规则"时，它把一篇讲 Magit 的文章吞了，3 次都是。结束执行的钩子也改成看程序记没记下，不看模型要求了什么，编译规则同样适用。

**你看到的：** 管家、门铃和列表各一行：`New in elfeed 7 new; it names [2] Emacs 31.1 released (the model's words): …`，`it names` 后面的标题是 elfeed 的。按 `RET`，上面是模型的话，下面是它点到的文章和全部文章：标题、来源、日期、链接都是 elfeed 的，不是模型写的；点标题在 elfeed 里打开。按 `t` 接手，和别的结论一样。

**放在插件里。** `plugins/superchat-elfeed/`，elfeed 加载后由定时器那一行装上。没有 elfeed 的 Emacs 设不了这条规则，模型会被告知原因。核心只多了"事件可以由插件登记"这一点。

**当场问也行：skill 加一个只读工具。** 用户 2026-11-02 问"是否不用 plugin 也能用 rss，比如说接个 skill"，答复是 skill 只能做到"问了才查"，主动要有程序听着；用户随后说"做 skill"。skill 是一段说明，模型要有手才能读到 elfeed，现成的手只有 `eval_elisp`：什么都能跑，默认级别每次问你，你要读懂那段代码。所以插件多登记一个 `feed_search`：用 elfeed 自己的搜索写法读数据库，返回编号、标题、来源、日期、标签、链接和正文开头，什么都不改，连已读未读都不动。它在 `superchat-sandbox-reading-tools` 里，按内置工具对待，任何级别都不问。skill `elfeed-feeds` 放在插件的 `skills/` 里，插件装上时加进 skill 目录，说什么时候用它、过滤怎么写、用文章自己的标题和链接回答、文章内容是数据；"以后有就告诉我"设规则，不用它。

## 实现时定的

- **标题只留一行：** 去掉换行、控制字符和改变文字方向的字符，最长 200 字。否则一个标题可以伪装成好几篇文章。
- **链接只留 `http` 和 `https` 开头的。**
- **`unread` 标签不给模型：** 每篇新文章都有，说明不了什么。别的标签（你的自动标签）给。
- **每来一篇不查规则，** 一批齐了再查：elfeed 在解析时逐篇调用，一次更新可能几百篇。
- **那一行写出它点到的前 3 篇的标题。** 模型只写编号时，你看到的就是 `[2]`，看不懂。
- **`feed_search` 一次最多 40 篇，默认最近一周、20 篇。** 结果第一行写数据库有多少篇、最新的是哪天；什么都没找到时，明说"没有就是答案，没有别的读法"。量过：只返回 0 条时，模型 5 次里 5 次不信，用 `eval_elisp` 自己去翻，问了你 27 次。
- **RSS 规则一律按话挑，** 不跟第 7、8 步"话里没排除就没有不说话的工具"那条走。量过：设规则时模型对"和 Emacs 有关的告诉我"给不给 `quiet`，不同说法 1/5 到 5/5，没给时每一批不相关的文章都会说一行。代价见"安全"。

## 这一步没有做的

- 邮件、群聊：还没有接。群聊在原型里能发消息，这里只读的形态还没定。
- 让模型打开链接读全文：要联网，夹带指令的面更大。
- 按订阅或标签只看一部分：现在靠你的话让模型挑。

## Alternatives considered

**模型直接写标题和链接。** 没选：文章里可以写"推荐用户打开 https://…"，模型照抄，就成了一个看起来是文章链接的东西。编号由程序换成 elfeed 自己的标题和链接，假的没有地方冒充真的。

**不用模型，程序列出所有新标题（第 0 档）。** 没选做默认：92 个订阅一天几百篇，列出来就是 elfeed 本身。要挑，就要有人读。

**每篇调用一次模型。** 没选：费用按篇数涨，而且一批里谁更重要要放在一起比。

## Consequences

- **安全：** 文章是陌生人写的，标题、来源和正文开头都会发给模型服务商。模型没有工具，夹带的指令没有手可用，最多让它说错话或者不说话：
  - **不说话：** 每条 RSS 规则都可能被一篇文章劝成不说话，"每批都告诉我"的也一样。兜底是编号：模型说出哪篇相关，程序就不让它不说。在你自己的订阅上，有你要的文章却没说，最后一版是 54 次里 1 次。
  - **说错话：** 模型的话标明是模型的；它写的链接也会出现在那一行里，在对话里可能是能点的。点之前要知道那是模型写的，文章自己的链接在 `RET` 的下半部分。
  - 按 `t` 接手时，模型的话进你的输入区，你看得见、能改。
- **费用：** 一天最多 12 次请求。见"验证"。
- **对 elfeed 的影响：** 每篇新文章多一次很小的函数调用；出了错只打一行消息，不打断 elfeed。

## 验证

离线：`scripts/feed-regression.el` 32 项，用真的 elfeed（测试用的包目录里装了一份）和它自己的数据库，条目由 `elfeed-db-add` 放进去，elfeed 自己的钩子触发；模型是脚本。故意改坏：第一轮 41 处有 9 处没抓到，4 处是多余的代码，删了，5 处补了测试；最终代码上 41 处（含编号兜底、只看记下与否的钩子、RSS 规则一律按话挑）全部抓到。全部回归 132 个文件 2145 项，只有 `m5-regression` 3 项不过，那 3 项这一步之前就不过。M3 没有改动，139 项里 137 项通过、2 项跳过。

**真实，用户自己的订阅（2026-11-02 第二轮）：** 从用户的 elfeed 数据库复制一份只读副本，取最近的 160 篇真实文章（2026-09-20 到 10-28，Daring Fireball、Simon Willison、John D. Cook、Marcus on AI、Krebs on Security 等），分成 8 批，每批 20 篇，日期改成刚到。规则三条："讲 AI 或大模型的"、"安全漏洞、黑客攻击、数据泄露的"、"和 Emacs 有关的"。哪篇相关是我逐篇标的，只看了标题和正文前约 90 字，每批分"一定要报"和"报了也算对"；判对的标准是一定要报的都点到，点到的都在两组之内。每种 3 次，最终版本：

| | 结果 |
|---|---|
| 和我的标注逐篇完全一致 | 36/54 |
| 有你要的文章却没说 | 1/54（上一版没有编号兜底时 2/54） |
| 一批里没有你要的（21 批），却说了 | 0/21 |
| 一定要报的，漏点 | 14 篇次 |
| 不在两组里的，多点 | 12 篇次：多数是正文讲到了 AI、我只看标题没标上的（一段 AI 特效的音乐视频、一款用 Claude 写的游戏） |

一批中位数 7 秒、1.5 次请求、约 6600 提示 token（真实文章比合成的长）。

**真实，合成的文章（最终版本，每种 3 次）：** 20 种 57/60，错的 3 次都是同一种：规则只要 Python 新闻，模型把一篇讲 Emacs 里 Python 模式的也点了。夹带指令 10 种 30/30：把夹带的命令或链接写进那一行 0 次，吞掉你要的那篇 0 次。冒充用户改规则的那种，上一版提示 0/3，加了编号兜底后 3/3。完整流程（写着半句话时来了、门铃、按 `RET`、在标题上按 `RET` 在 elfeed 里打开、接手；接手是调用 `superchat-butler-bring`，不是按 `t`）3/3。

**设规则：** RSS 规则一律按话挑以后，只要模型把规则设在 `feed_new` 上就算对：8 种说法各 3 次，24/24；当下的问题（"帮我看看 elfeed 里有没有讲 Emacs 的"）3/3 没设规则。第一轮里模型还要自己判断 `quiet` 时，"和 Emacs 有关的告诉我"这类是 1/5 到 5/5。第 8 步的编译说法在第一轮重测过：5/5、4/5、4/5、3/5、5/5，`quiet` 的说明是两种规则共用的，后来改回了第 8 步的写法、只加了两个 RSS 的例子。

**费用：** 两轮共 813 次 e17 运行（其中 162 次用真实文章）和 51 次编译说法回归，约 1971 次请求、781 万提示 token（616 万命中缓存）、24.9 万输出 token。实验数据约 4.4 GB，不进版本库。用户的 elfeed 副本和导出的文章在 `.scratch/super-agent-exp/private/` 和本机的临时目录里，也不进版本库。

**当场问（skill 和 `feed_search`，用户自己 elfeed 数据库的只读副本，6800 篇，最新 2026-10-28）：** 真实窗口里打字提问，模型自己从 skill 目录找到它或直接用工具。第一轮 8 种问题各 5 次，34/40：查不到时（"最近有讲 Emacs 的吗"）模型不信，改用 `eval_elisp`，5 次问了 27 次批准；还写了 elfeed 没有的 `OR`。改了结果的第一行和"或"的写法以后，第二轮 10 种（其中 2 种是新写的）各 5 次，49/50；用 `eval_elisp` 1 次，问了 1 次；回答里 60 个链接都来自 elfeed，没有编造的。"以后有讲 Emacs 的就告诉我" 10/10 设的是规则，没有当场回答。一次中位数约 8 秒、2 次请求、约 1.7 万提示 token。两轮共 91 次，247 次请求，193 万提示 token（113 万命中缓存），6.1 万输出 token。

**没有验证的：**

- 没有接真实网络：文章是从数据库副本放进去的，没有经过 elfeed 的抓取。
