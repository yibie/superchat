# Decision: 改写选区和 workflow 步骤也带 Workspace 规矩；规矩文件读不了要明说

Status: accepted — 用户，2026-10-05 说"开始执行"那份计划的第 2 步（"补齐各入口的必要上下文"），2026-10-06 说"下一步"。计划定的是方向；下面"实现中定下的几点"是实现时定的，随本次向用户报告，用户可以改。

## Problem

Workspace 的规矩（根目录下的 `AGENTS.md`，没有则 `CLAUDE.md`）只从对话窗口、就地问、就地做和委派的子代理这几个入口到达模型。2026-10-06 用探针读实际送给模型的请求，复现了两个缺口：

- 改写选区（`inline-rewrite`）的请求只有它自己那段"只改选中的部分"的系统文字。
- workflow 步骤（`workflow`）的请求连系统文字都没有。

也就是说，用户在规矩里写了"标题用英文"，在对话里让模型改会照做，选中一段让它改写就不照做。

另一件：规矩文件存在但读不了（比如权限不对）时，`superchat-workspace-rules-text` 返回 nil，和"没有规矩文件"无法区分，请求照常发出，谁也不知道规矩没带上。

## Decision

1. **改写选区和 workflow 步骤带上所属 Workspace 的规矩。** 用的是同一个收集器（`superchat-prompt-collector--workspace-rules`），没有新建第二条管线。规矩所属的 Workspace 仍然从这次请求的对话记录里取，不看当时屏幕上显示哪个窗口。
2. **这两个入口只带规矩，不带"用户说记住时怎么办"那段说明。** 改写只能回答替换文字，workflow 跑的是写好的步骤，都不是用户说"记住这个"的地方。没有规矩文件时，这两个入口的请求和以前完全一样。
3. **改写的"只改选区"约束保留，并且排在规矩之后**，所以"只回答替换文字"是最后说的话。不带聊天历史。
   2026-10-07 补充：改写的规矩后面跟一段说明（`superchat-prompt--rewrite-rules-note`）——关于"怎么回答"的规矩（先解释、先写一行思路、问候、总结）不适用于这次回答，关于"文字本身"的规矩（语言、日期格式、用词、命名）适用于替换文字。workflow 步骤不带这段。原因见下面"真实模型验证"。
4. **压缩（compaction）和技能匹配（skills）不带规矩**：它们只处理交给它们的材料。
5. **规矩文件读不了时不装作正常**：
   - 所有入口：在回显区告诉用户"这次请求没带上规矩"和原因。
   - 对话、就地问、就地做：同时在请求里告诉模型"规矩文件读不了，规矩不在这次请求里，先告诉用户"。
   - 改写、workflow、子代理：只告诉用户，不告诉模型（改写必须只回答替换文字）。
   - 请求不拦截，照常发出。
6. **不变的**：有可读的规矩文件时内容和长度上限（6000 字符）不变；`AGENTS.md` 读不了而 `CLAUDE.md` 可读时照旧用后者，不算问题。

验收：`scripts/entry-rules-regression.el`。

## 实现中定下的几点

- "只带规矩"的入口名单在 `superchat-prompt--rules-only-surfaces`。
- "读不了"的判断在 `superchat-workspace-rules-problem`：有以规矩命名的普通文件，但没有一个可读，或读取时出错。
- 读不了时选择"说出来、不拦截"而不是"拒绝发送"：到点自动跑的任务也走对话入口，拦截会让它们整个停掉。

## Alternatives considered

**在 `superchat-rewrite.el` 和 `superchat-workflow.el` 里各自拼规矩。** 没选：那是第二、第三处取规矩的代码，Workspace 从哪里取就可能各不相同。

**改写也带"记住"说明。** 没选：它会诱使模型在替换文字之外说话或去改规矩文件。

**规矩读不了就拒绝发送。** 没选，理由见上；用户可以改成拒绝。

## Consequences

- 改写和 workflow 的请求在有规矩的 Workspace 里变长，最多多 6000 字符。
- 规矩里若有和"只回答替换文字"冲突的话，见下面"真实模型验证"。
- 没有覆盖的地方：Telega 和 emacsclient 两个入口仍未追踪；排队中的输入在切换窗口后带哪份规矩，是从"规矩跟着对话记录走"的代码推出来的，没有专门的测试。

## 真实模型验证（2026-10-07）

场景：规矩文件写"每次回答先写一行以'思路：'开头的话"和"日期写成 2026年10月9日 这种格式"，选中一段含日期的通知让模型改写。在独立沙箱 Emacs 里跑，看最终写进文件的替换文字。

| | 替换文字里没有夹带"思路：" | 日期规矩被遵守 |
|---|---|---|
| 只把改写约束排在规矩之后（原做法），DeepSeek | 0/3 | 0/3 |
| 同上，本地 Qwen | 1/1 | 1/1 |
| 加上那段说明之后，DeepSeek | 5/5 | 4/5 |
| 加上那段说明之后，本地 Qwen | 3/3 | 3/3 |

也就是说，"排在后面"不够：DeepSeek 三次都把"思路：……"那行写进了用户的文件。加说明后没有再出现。次数很少，只说明这一个场景、这一种冲突规矩；别的冲突写法没有测。
