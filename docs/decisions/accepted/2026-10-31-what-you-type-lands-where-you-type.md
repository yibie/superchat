# Decision: 你打的字落在你打字的地方

Status: accepted — 用户，2026-10-31。我问"是否不等其它决定，先修这四个缺陷？"，用户答"1. 是。"审阅屏的规则用户先说"不理解这个交互，说人话"，我换成具体的选择后，用户选了"弹出来，光标不动"。审阅屏的键，我问"要把那 12 个无害的键放回审阅屏吗？"，用户答"放回"。"实现时定的"各条都可以改。这条记录替换[光标留在你去的地方](2026-10-31-the-cursor-stays-where-you-went.md)里"走开"的定义，那条记录的其余部分不变。

## Problem

[真实窗口、真实按键、真实模型的实验](../../research/super-agent.md#查出的现有缺陷)查出四个缺陷，都不依赖主动 Agent：

1. 审阅屏过来时，正在打的键变成了它的命令：`s` 存盘，`u` 加空格撤销改动并写盘。
2. 执行结束或一行系统消息插入时，光标被挪出输入区，后面的字报 `Text is read-only` 后丢失。
3. 定时任务发送后，用户回到对话，光标还在已发送的那条消息里，打的问题进了旧消息，没有发出去。
4. 模型的 `eval_elisp` 在用户正打字的 buffer 里移动光标，用户接着打的字插进了代码中间。

## Decision

**审阅屏什么时候出现，光标跟不跟过去：**

| 你在做什么 | 屏幕 | 光标 |
|---|---|---|
| 发完话盯着对话，手没动 | 出现 | 跳过去，和 2026-09-25 的裁定一样 |
| 在输入区写下一句 | 出现，占代码窗口的位置 | 不动 |
| 回到旁边的代码窗口，打字或只是看 | 出现，占代码窗口的位置（只有一个代码窗口时是下半部分） | 不动 |
| 刚按过键（2 秒内），不管在哪 | 出现 | 不动 |
| 正在用小缓冲区 | 出现 | 不动，用完也不跳过去 |
| 关了对话窗口，或对话在别的 tab | 不出现，回显区和 `superchat-pending` 里有未保存的说明 | 不动 |
| 后台报告启动的执行 | 不出现 | 不动，和之前一样 |

**审阅屏只放行明确列出的键。** 可打印的键里，有作用的是 `s`、`n`、`q`、`g`、空格，以及 `diff-mode` 里只移动、复制或看帮助的 12 个键：`p`、`N`、`P`、`{`、`}`、`<`、`>`、`W`、`r`、`w`、`h`、`?`。其余一律只提示一句，包括 `o`：它把光标带到源文件，后面打的字会进代码。这样 Emacs 以后给 `diff-mode` 加新的单键（Emacs 32 加了 `u`、`@`）也按不到。

**系统行不动光标。** 对话里插入一行系统消息时，用户的光标留在原来的文字上，不管它在输入区还是正往上翻。

**定时任务发送后，光标在输入区的窗口，光标回到新的输入区。** 正往上翻的窗口不动。

**`eval_elisp` 不移动用户所在窗口的光标。** 表达式结束后，如果选中的窗口和它显示的 buffer 都没变，光标放回原来的文字上。

**审批卡片不能打字，回答后光标回到输入区。** 2026-11-01 的[真实运行](../../research/super-agent.md#审批在哪里)里，用键盘按完按钮，接着打的字进了卡片（`next wordsAllowed once`，2/2）。我问"是否接着修"，用户答"同意"。卡片的文字是只读的，按钮照常能按。问题答完时，选中窗口的光标如果在卡片上，就到输入区末尾，写了一半的话不动。光标在别处的（鼠标点、列表、别的窗口）不动。

## 实现时定的

- 2 秒是 `superchat-changes-review-quiet-seconds`，可以改。它取自实验里比较过的值（R4、R5），没有比较过别的数字。
- "手没动"用 `current-idle-time` 判断。批处理 Emacs 没有人在键盘前，算手没动。
- 模型 2 秒内就改完时，光标不跳过去，屏幕照样出现。这种情况真实运行里没有遇到过，为它加一个延迟再跳的定时器不值得，那个定时器本身又是一次抢光标。
- 小缓冲区用完后不再跳过去。之前的做法是等它结束再选中，那正好是用户手上在忙的时候。
- 只判断从对话发起的执行是否"还在原地、输入区为空"。就地问、就地做、workflow 没有这个位置，只看手有没有动和小缓冲区。
- 放行的键之外，`RET`、`TAB`、`M-n`、`M-p`、`C-x` 这些不是打字时会碰到的键不变。`C-c` 下会改源文件的组合也挡住了（`C-c RET a`、`C-c RET n`、`C-c M-u`、`M-K`、`C-c C-l`、`C-x 4 A`）。
- 放回的 12 个键在键表里逐个写明命令，不落到 `diff-mode` 自己的键表。这样以后 `diff-mode` 或 diffs.el 给这些字母换了含义，打字的人也碰不到。
- `r` 不直接绑 `diff-restrict-view`。Emacs 默认禁用这个命令，按下去先问一句，后面的键都被这个问题吃掉。真实窗口里，"try to"落到审阅屏，`y` 和空格答了"是"，init 文件被写入 `(put 'diff-restrict-view 'disabled nil)`（修复前 1/1，已提交的版本 1/1，修复后 0/3）。所以 `r` 绑到 `superchat-changes-review-narrow`，它直接调用那个命令，不问也不写。在审阅屏以外，那个命令仍然是禁用的。
- `w` 的命令 `diff-kill-ring-save` 是 Emacs 31 才有的。Superchat 支持 Emacs 30，那里 `w` 继续只提示一句。
- 系统行只在已有输入区时保留光标。还没有输入区时（对话刚打开）行为不变，光标落在新建的输入区。
- 定时任务的修法放在 `superchat-timer--start-task`。其它不是用户发的消息（`superchat-work-wake` 用新对话；`superchat-genui` 和就地发送先选中了对话窗口）没有这个问题。
- `eval_elisp` 放回光标只对从对话、子代理、workflow 等来的执行生效。`inline-act`、`inline-ask` 不放回，用户就在那个 buffer 里发话，移动光标可能正是要求。没有执行的直接调用也不放回。
- 选中的窗口不是显示那个 buffer 时，`with-current-buffer` 里的 `goto-char` 本来就不影响窗口的光标，不用管。表达式换了选中的窗口或窗口里的 buffer，算有意为之，不放回。
- 模型因此没法用 `eval_elisp` 移动用户所在窗口的光标。用户留在对话里时，模型仍然可以用 `set-window-point` 移动代码窗口的光标。

## Alternatives considered

**我上轮建议的规则：对话看得见就算在原地，屏幕过来并拿光标。** 没选：实验里 5 次键全落上去，2 次撤销并写盘。

**回到代码窗口时不显示，只提示一句。** 用户选了显示。代价写在 Consequences。

**只挡 `u` 和 `@`。** 没选：黑名单已经漏过一次，漏的是新版 Emacs 加的键。

**`r` 继续挡住。** 没选：用户要放回，包一层就能去掉那个问题。

**系统行一律用 `save-excursion`。** 没选：对话刚打开时光标要落在新建的输入区。

**`eval_elisp` 的工具说明里要求模型用 `save-excursion`。** 没选：说明管不住模型，实验里 12 次运行有这种 eval。

**只在用户最近按过键时放回光标。** 没选：实验里用户打一阵停一下时也出过事（`burst R5` 第 3 次）。

## Consequences

- 用户在代码窗口时，代码区变成一半高，审完按 `q` 恢复。要按 `C-x o` 才能按 `s`。
- 审阅屏上 `diff-mode` 的单键里，`o` 不能用，改用 `RET`。会改源 buffer 或视图内容的键（`u`、`@`、`k`、`K`、`A`、`R`、`v`）也不能用。
- 打字的键落到审阅屏时，`h`、`?` 会多开 Help 窗口，`r` 会收窄视图（提示行也看不到了，按 `W` 或 `g` 恢复），`w` 会往 kill ring 加一条。
- `n` 仍是"不存、下一个"，而 `p` 是"上一个改动"，两者不对称。下一个改动是 `M-n`。这个不对称以前就有。
- `/work` 的轮次在用户回到代码窗口时又会停下来等审阅（[审阅屏记录](../implemented/2026-09-24-editor-mode-agent-mode-and-review-screen.md)里的"it waits for your review"），这是上一版规则去掉的。关了对话窗口时仍然不等。
