# `read_file`：读取没有 buffer 打开的本地文本文件

Status: implemented（2026-09-18，提交 9d967e39，真实模型复验通过）；此前为 accepted — 用户 2026-09-18 选定 1(a)、2(a)、3(a) 并逐条给出边界；本文把它们落成契约。实现状态记在[路线图](../../roadmap.md)。

## 背景

M6 的真实模型验收里发现（`.scratch/m6-permissions/issues/01-no-tool-reads-an-unvisited-file.md`）：内置工具能写文件（`write_file`）、保存文件（`save_buffer`）、读 live buffer（`read_buffer`），但没有任何工具能读一个没有 buffer 打开的文件。模型想看 `~/.emacs.d/init.el` 只能用 `eval_elisp`（完整 Emacs 控制，每次都问）；题目禁用 `eval_elisp` 时它彻底读不到，两个场景各空转 10 分钟超时。DeepSeek Harness 有对应结构：`read` 工具（路径、起始行、行数；2000 行、单行 2000 字符、50 KiB 三个上限），读在任何沙箱模式下都不受限制。

## 决定

### 1. 形态：`read_file`，直接读磁盘，不创建文件访问 buffer

- 参数：`path`（必填）、`offset`（可选，从 1 起的首行，默认 1）、`limit`（可选，返回的最大行数，默认且最大 2000）。`offset`、`limit` 给了就必须是正整数，`limit` 超过 2000 报错。
- "不打开 buffer"的准确含义：**不创建 visiting buffer**。实现可以用临时 buffer 装字节，但不走 `find-file`：不触发 major mode、文件局部变量、`find-file-hook`，用户的 buffer 列表不变。
- **始终读磁盘版本**。已有 visiting buffer 且有未保存改动时，照常返回磁盘内容，同时在结果里明确标注"buffer NAME 正在访问这个文件且有未保存改动，磁盘内容可能落后；用 `read_buffer` 看未保存内容"。不自动保存、不同步、不改那个 buffer。
- **只支持本地普通文本文件**。以下明确报错，且**在读任何字节之前**按文件名和属性判定，避免在特殊文件上阻塞：路径为空或不是字符串；TRAMP／远程路径；不存在；目录；非普通文件（设备、FIFO、socket 等——符号链接先解析，判定落在它指向的对象上）；不可读；超过大小上限。**二进制**是唯一在读入之后判定的：普通文件读进临时 buffer 后发现 NUL 字节即报错，不返回任何内容。
- **查找未保存的 visiting buffer 时不运行任何文件名处理器**：比较其它 buffer 的文件名时 `file-name-handler-alist` 为空，访问远程文件的无关 buffer 不会把它的处理器带进一次本地读取。
- **截断计数只算实际返回的行**：一条超长行若被字节上限挡在结果之外，它没有被"截断后返回"，头部不得报告它；续读到它的那次调用才报告。
- **不经过文件名处理器。** 读取时 `file-name-handler-alist` 为空：没有 TRAMP，加密文件（`.gpg`）不会弹口令提示，压缩文件不会被透明解压——它们按原始字节判定，通常报"二进制"。
- **超过 20 MiB 的文件报错、不读入。** 统计总行数需要把文件读进内存，这个上限防止一次调用拖住 Emacs（实现时补的边界，dsh 用流式读取解决同一问题）。
- 编码：按 Emacs 的常规检测解码文本（不执行文件局部变量里的 `coding:` 以外的任何东西——因为不走 `find-file`，局部变量本来就不处理）。

### 2. 输出与上限

三个上限，取自 dsh 的默认值：

| 上限 | 值 | 触发时 |
|---|---|---|
| 行数 | 每次最多 2000 行（`limit` 的默认值和最大值） | 窗口之后还有行：头部注明，并给出续读用的 `offset` |
| 单行长度 | 2000 字符 | 该行截断，行尾加 `... (line truncated to 2000 chars)`，头部注明有行被截断 |
| 总字节 | 所选行合计 50 KiB（UTF-8） | 在行边界停止，头部注明"按字节上限截断"，并给出续读用的 `offset` |

结果 = 头部 + 一行 `Content:` + 正文。头部第一行 `File: 实际路径`，第二行 `Lines: A-B of N (complete file)` 或 `Lines: A-B of N (NOT the complete file: 原因…)`，有未保存 visiting buffer 时再加一行 `Note: buffer NAME …`。头部写明：解析后的实际路径、文件总行数、本次返回的行范围、每一种发生了的截断和续读方法。**正文无行号**，是文件的原文行（`edit_buffer`、`write_file` 需要精确文本）。**被截断的内容不能被呈现成完整文件**：只要三种截断任意一种发生，头部必须出现"不是完整文件"的明确字样；没有截断且窗口覆盖全文时，头部写明"完整"。空文件、`offset` 超过总行数都是正常结果（零行），头部如实说明。

### 3. 权限：读由操作系统决定，三个档位同一规则

这是一条明确的产品选择，不是遗漏：

- **文件能不能读，由当前 Emacs 进程的操作系统权限决定。** `read_file` 自身不要求批准，不检查 workspace，不设敏感路径名单；`read-only`、`workspace-write`、`danger-full-access` 三个档位的读取规则完全相同（dsh："every mode permits reading"；与现有 `read_buffer` 一致）。
- **读出的内容进入当前模型上下文；使用远程模型时，会被发送给对应的服务商。** 这包括工作区之外的文件。M6 之前读未打开的文件只能走每次询问的 `eval_elisp`，所以本工具新开了一条"不问就能读"的路——这是已知并接受的代价，README 要写明。
- **沿用现有执行管线。** 调用仍经过 `superchat-tool-execute`：`tools/pre-execute` 照常运行，插件把它收紧为 `ask` 或 `deny` 时照常生效；Tape 审计不变。工具类别是内置工具（档位规则 `allow`）。"不进批准流程"的准确说法是"工具自身不要求批准"。
- 不带升级参数（`sandbox_permissions`／`justification`）：它不是写工具，没有可升级的东西。

### 4. 工具面

- 加入默认工具集 `superchat-llm-default-tool-names`（及 `superchat-select-tools.el` 里的手抄副本），位置在 `read_buffer` 之后。
- **不扩大显式名单**：用户把 `superchat-llm-tool-names` 设成自己的列表、或 Preset／Request 显式给出 `:tools` 时，名单里没有 `read_file` 就不提供。
- 不进 inline-ask 的基线（那份基线是四个固定的读工具，本次不动）。
- 描述里教模型：看没打开的文件用它而不是 `eval_elisp`／shell；大文件用 `offset`／`limit` 续读；live buffer 的未保存内容用 `read_buffer`。

## 验收

1. 独立回归文件（不进 M3／M5／M6 的文件），每条先在缺口处为红：基本读取与头部；不创建 visiting buffer、不触发 `find-file-hook`；未保存 visiting buffer 时返回磁盘内容并点名 buffer；三种截断各自的头部字样与续读；正文无行号；各类拒绝（远程、目录、不存在、FIFO、二进制、坏参数）；三个档位同样可读；经真实管线调用不询问；`tools/pre-execute` 的 `deny`／`ask` 生效；默认工具面包含它、显式名单不被扩大。
2. 既有套件、canonical smoke、Kernel 检查、加载、编译警告不变；默认工具面变化只允许体现在记录工具名单的基线上。
3. 真实模型复验（qwen3.8-27b）：用 M6 验收里受阻的两个场景（chat、act：往 `~/.emacs.d/init.el` 末尾追加一行，禁用 `eval_elisp`／shell），分别记录"成功读取磁盘内容"和"后续写入遵守现有升级流程"。T2 完成时延继续单独评价。

## 不做

`open_file`（把文件打开成 buffer）、目录列举、按模式搜索文件、图片读取、敏感路径名单、读取的 workspace 限制。
