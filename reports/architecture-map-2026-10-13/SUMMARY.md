# Superchat architecture walk — final summary

Baseline: HEAD `b4f0548f4851a9cab4eec984427babc41d6ac719`. This is a static source walk, not a test report. Product code, tests and existing docs were not changed. MAP.md contains the nodes; CONTRADICTIONS.md contains quoted disagreements, implementation traces and costs. C11's HEAD defect and attribution to `b3391425` were confirmed by the steering architect; that confirmation is not represented as a new local reproduction.

## The architecture in ten lines

1. **Code fact:** An Envelope is submitted through the driver, but Runtime owns Run/Step identity, terminalization and cancellation; a producer callback does not establish durable success (`superchat-pipeline.el:345–435`, `superchat-runtime.el:2646–2851`).
2. **Code fact:** Session, Scope, Actor, View and Run are different identities: a shared Session does not imply a shared buffer lifetime or an identical borrowed execution Scope (`CONTEXT.md:9–83`, `CONTEXT.md:174–184`, `superchat-runtime.el:3370–3522`).
3. **Code fact:** Tape stores facts; projections and checkpoints interpret them. Runtime registries, FIFO continuations, retry budgets, overlays and generated function cells are maintained outside Tape (`superchat-projection.el:21–109`, `superchat-runtime.el:109`, `superchat-work.el:851–913`, `superchat-synthesis.el:210–227`).
4. **Code fact:** Composition has 33 default rows, not a fixed Stage registry; Scope registration cleanup does not automatically reverse arbitrary module mutation (`superchat-plugin.el:260–267`, `superchat-pipeline.el:508–587`, `docs/design/plugin-architecture.md:17–27`).
5. **Code fact:** Permission decisions and effect recording meet at the common tool seam, but captured authority has lifetimes of its own: synthesized closures and prepared child contexts expose the C1/C12 gaps (`superchat-tool-execution.el:389–407`, `superchat-synthesis.el:210–227`, `superchat-subagent.el:932–952`).
6. **Code fact:** Start needs a live host, not a window; chat's permissive Sink can record success after View death, but a dead strict overlay Sink converts the ending to cancelled/sink-lost. Preset-owner retirement is another cancellation path (`superchat-runtime.el:3270–3297`, `superchat-render.el:1617–1626`, `superchat-runtime.el:2670–2740`, `superchat.el:2014–2066`).
7. **Code fact:** In-place commands use Workspace/temporary conversation routing, no general earlier history, and explicit overlay follow-up context; rewrite/annotation are tool-free while inline act is not (`superchat.el:3708–3736`, `superchat-inline.el:96–114`, `superchat-inline-act.el:262–294`, `docs/architecture.md:117–119`).
8. **Code fact:** Timers and Work wakes can create undisplayed chat Views; goal rounds instead depend on an existing View and process-local continuing state. Restart reconstruction is not resurrection of these continuations (`superchat-timer.el:354–383`, `superchat-work.el:914–953`, `superchat-work.el:1223–1229`, `superchat-work.el:1306–1349`).
9. **Code fact:** The no-progress brake durably changes the Work Record to waiting-user, then advertises a resume command which refuses that state: C11 is a current user-facing defect, not merely old documentation (`superchat-work.el:1439–1455`, `superchat-work.el:1519–1523`).
10. **Inference:** The largest architectural risk is disagreement at boundaries—Run authority retained past its owner, recorded truth confused with delivery, or a feature promise stronger than the shared permission policy—not the mere existence of non-Tape state (`superchat-runtime.el:1423–1503`, `superchat-agent-loop.el:104–119`, `superchat-sandbox.el:304–330`).

## What this walk did not cover

- No Emacs execution, ERT/smoke/byte compilation, provider request, tool effect, Telega send, window manipulation or live database access. No performance measurement or restart/race/fault-injection experiment was performed.
- C1's reported Session occurrence was not inspected in the live Tape; C11's interactive/commit attribution is the steering architect's confirmation. Other conditional hazards are source analyses, not reproduced user incidents.
- The map is not a full reverse-call graph. Caller/callee lists are traced architectural examples. Registration/reducer reads of Plan, Artifact, Memory and Experience are not exhaustive audits of those subsystems' UI, migrations or every learner/recovery path.
- Org Babel and Magit were identified through their rows/declared blocking contract, not walked end to end in this Surface round. Third-party providers, MCP servers, Telega/TDLib, Emacs project/window internals and user-installed listeners/advice remain external dependencies.
- No persistent callback, generated-function or buffer contents recovery is inferred merely from durable fact existence. Telega's live Session transcript/grant cache, workflows' continuations and retry/continuing tables were not tested across restart.
- The description inventory covers the current READMEs, CONTEXT, architecture, all current docs/components files, inspected docstrings and relevant linked decisions. It is a manual semantic grouping, not a proof that every repeated sentence in every historical decision/report/design document was found. Historical reports, .scratch evidence and archived specifications were not treated as current contracts.
- Round 4 corrected earlier map descriptions against HEAD: Workspace/timer descriptor names, Workflow reducer input, and chat-recording/permission observer names. These were report corrections, not product changes (`superchat-tools.el:2457–2463`, `superchat-tools.el:1501–1515`, `superchat-workflow.el:397–420`, `superchat.el:5406–5407`, `superchat-prompt-hooks.el:1185–1186`).
